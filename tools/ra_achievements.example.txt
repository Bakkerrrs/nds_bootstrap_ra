# WHY THIS FILE IS NOW MOSTLY WATCHES

# The first run with real definitions established that the machinery works and that the

# which the third definition was written for.
#
# That is not something to fix by guessing at another definition, which costs a play
# session per attempt. It is something to fix by looking at what the memory actually holds.
# So this round measures first: the watches below report resolved addresses and values into
# the snapshot's results[] at +0x30, and the answer decides what the definitions should say.
# ---------------------------------------------------------------------------------------


# results[0] -- Current Stage, [32-Bit] per the code notes, 0x00 = Stage 1.
# If this reads something unrelated during play, the code notes do not describe this ROM
# and every address below is suspect too.
W:1593d0:4

# results[1] -- the game state, through the pointer the notes describe. Note `W24:`, not
# `W:`: the previous run proved the word stored there is not a DS address. Three direct
# watches resolved and this chain came back BAD_TARGET, while rcheevos -- which masks to
# 24 bits -- refused nothing at the same location. The two disagreeing is what identified
# the walker's model as wrong rather than the address.
#   0x159164  [24-Bit Pointer] Game state pointer
#     +0x9c   [32-Bit] Game state, 0x02 = Fever
#
# This is the one that matters. `address` in the snapshot shows where the chain resolved,
# so a plausible 0x02xxxxxx there means the pointer is real, and `value` shows the state.
# Watch it while entering Fever Time: if it never becomes 2, the offset or the meaning is
# wrong. If `status` is 4 (BAD_POINTER) the word at 0x159164 is not a usable pointer, which
# would mean even the masked pointer is not usable and the address itself is wrong.
W24:159164:4:9c

# results[2] -- Number of Stages Completed, [8-Bit] 0x00-0x05.
# A slow, small, easily verified counter: a second opinion on whether these addresses
# describe this ROM at all.
W:1593c4:1

# rather than inferred from a status code. If `value` here is 0x0215xxxx the mask changes

W:159164:4
