# Definitions and watches, one per line. Copy to
#   sd:/_nds/nds-bootstrap/ra_achievements.txt
#
# '#' comments and blank lines are ignored. Only the first four watches reach the
# snapshot's results[] at +0x30.
#
#   an achievement:  RetroAchievements memaddr syntax, activated in the runtime
#   a watch:         W:<address>:<size>[:<offset>...]     pointers are DS addresses
#                    W24:<address>:<size>[:<offset>...]   pointers are 24-bit console
#
# Addresses are console addresses: RetroAchievements maps DS system RAM at 0, so 0x159164
# here is 0x02159164 on the console.
#
# ---------------------------------------------------------------------------------------
# A CANARY THAT ACTUALLY ANSWERS, THIS TIME
#
# The previous round used Extreme Mode Unlocked as the canary and it read zero -- which
# proved nothing, because that value comes from saved data and the reading was taken on a
# freshly downloaded ROM with no save, on the title screen. A test that returns the same
# answer whether the hypothesis is true or false is not a test. That was a design mistake,
# not a result.
#
# 0x13c9c4 has none of that problem. It is documented as "In Title Screen/Records Loop",
# 0x01 in the loop and 0x00 outside it -- runtime state, no save involved, and a state you
# can put the console into deliberately. Two readings, one on the title screen and one in
# game, and the pair is unambiguous:
#
#   1 then 0   the addresses describe this cartridge; the game-state offset is the problem
#   0 then 0   nothing is there
#   the same nonsense both times, or values that never change: a systematic offset between
#              RetroAchievements' addressing and ours
# ---------------------------------------------------------------------------------------


# results[0] -- THE CANARY. [32-Bit] In Title Screen/Records Loop.
# Expect 1 on the title screen and 0 during play. This one value decides the round.
W:13c9c4:4

# results[1] -- [24-Bit Pointer] Main Menu information. A second, independent check on the
# same state from a different address: non-zero on the menu is what a live menu structure
# looks like. Read raw rather than followed, because its value is the evidence.
W:155288:4

# results[2] -- the raw word at the game state pointer. Last round it read 0x02159158,
# a plausible DS address, so something is there -- the question is whether it is what the
# notes think it is.
W:159164:4

# results[3] -- [32-Bit] Current Stage. It read 2 on the title screen, which the notes say
# means Stage 3-A. On the title screen that is either stale data from a previous run or the
# wrong field; watching it change as you start a run distinguishes those.
W:1593d0:4


# Kept so the runtime keeps evaluating and the per-frame cost stays comparable. It cannot
# fire until the addresses are settled, and nothing this round depends on it.
I:0xW159164_0xX00009c=2_I:0xW159164_d0xX00009c!=2
